# دليل نظام CRM Mini — المكونات وبيزنس كيسز خطوة بخطوة

هذا الدليل يشرح **مكونات النظام** ثم يسير معك **خطوة بخطوة** عبر دورة حياة الفرصة (Opportunity) وكل السيناريوهات البديلة (الرفض، الإرجاع، التعليق، الإلغاء…).

---

## 1) ما هو النظام؟

**CRM Mini** نظام لإدارة دورة حياة فرص العطاءات والمبيعات المسبقة (Presales & Bids):

استلام الفرصة → التأهيل → بناء العرض → الاعتماد → التقديم → تسجيل النتيجة → التعاقد.

| الطبقة | التقنية |
|--------|---------|
| الواجهة | Angular 19 + Material + ترجمة عربي/إنجليزي (RTL) |
| الـ API | .NET 8 + MediatR + JWT |
| قاعدة البيانات | SQL Server (أو InMemory للتطوير/التجربة) |
| مسار الـ API | `/api/v1` |

### عناوين التشغيل المحلي الشائعة

| الخدمة | العنوان |
|--------|---------|
| الواجهة (Angular) | `http://localhost:4200` |
| الـ API / Swagger | `http://localhost:5088` / `http://localhost:5088/swagger` |
| كلمة مرور مستخدمي التجربة | `Passw0rd!` |

## 2) مكونات النظام (Architecture)

### 2.1 الطبقة الخلفية (Backend)

```
Crm.Api              ← Controllers + JWT + Swagger
Crm.Application      ← أوامر/استعلامات MediatR + سياسات الصلاحيات
Crm.Infrastructure   ← EF Core + محرك سير العمل WorkflowEngine + البذور Seed
Crm.Domain           ← الكيانات، الحالات، الأدوار، أكواد البوابات
```

**محرك سير العمل (`WorkflowEngine`)** هو مصدر الحقيقة للانتقالات بين الحالات وفتح/إغلاق بوابات الاعتماد (Gates). لا يُفترض أن تُغيَّر الحالة «يدوياً» للحالات التي لها آثار جانبية (بريد، عقد، بوابة…) إلا عبر الإجراء المخصص لها.

### 2.2 الطبقة الأمامية (Frontend) — أهم الشاشات

| المسار / المنطقة | الوظيفة |
|------------------|---------|
| تسجيل الدخول | JWT، تبديل اللغة عربي/إنجليزي |
| لوحة المعلومات Dashboard | مؤشرات، مهامي، مخططات الـ Pipeline |
| الفرص Opportunities | قائمة / كانبان / تقويم + إنشاء وتفاصيل |
| التأهيل Qualification | مسار التأهيل واجتماع التأهيل |
| العروض Proposals | التكاليف، التسعير، المنفّذ، خطاب الضمان |
| الاعتمادات Approvals | بوابات القرار المعلّقة |
| التقديم Submission | تقديم الفرصة وتسجيل النتيجة |
| التعاقد Contracting | العقد وجولات التفاوض والاعتماد |
| التقارير Reports | قمع التحويل، ربح/خسارة، الالتزام بالمواعيد… |
| الإدارة Admin | مستخدمون، أدوار، صلاحيات، قوالب بريد، إعدادات سير العمل |
| الإشعارات / الوارد | تنبيهات البوابات والمواعيد |

### 2.3 الوحدات الوظيفية (Domain Modules)

| الوحدة | ماذا تدير؟ |
|--------|------------|
| الفرص | الفرصة، العميل، المالك، المنفّذ، المواعيد النهائية، النطاق |
| سير العمل / البوابات | تعريفات البوابات، نسخ القرار (GateInstance)، انتقالات الحالة |
| التأهيل | مسار الاجتماع، قرار خط الخدمة، محضر الاجتماع |
| العرض | تكلفة تقديرية، تسعير بإصدارات، ردود خط الخدمة، خطاب الضمان (مسار موازٍ) |
| التقديم | سجل التقديم، نتيجة ربح/خسارة |
| العقود | عقد مرتبط بالفرصة الفائزة، تفاوض، اعتماد توقيع |
| التعاون | مرفقات، ملاحظات، تعليقات (Chatter)، أنشطة مجدولة |
| التقارير | KPIs، Pivot، تصدير Excel/CSV |
| الهوية والصلاحيات | مستخدمون، أدوار، مصفوفة صلاحيات قابلة للتعديل |

## 4) دورة حياة الفرصة — المراحل والحالات

### 4.1 المراحل (Stages)

| الترتيب | الرمز | الإنجليزية | العربية |
|---------|-------|------------|---------|
| 1 | `QUALIFICATION` | Qualification | التأهيل |
| 2 | `RESPONSE_DEVELOPMENT` | Response Development | تطوير الرد |
| 3 | `SUBMISSION` | Submission | التقديم |
| 4 | `CONTRACTING` | Contracting | التعاقد |

### 4.2 الحالات (Statuses) حسب المرحلة

#### مرحلة التأهيل

| الرمز | العربية | نهائية؟ |
|-------|---------|---------|
| `AWAITING_ASSESSMENT` | بانتظار التقييم | لا |
| `QUALIFIED` | مؤهل | لا |
| `NOT_QUALIFIED` | غير مؤهل | نعم |
| `CANCELED` | ملغى | نعم |

#### مرحلة تطوير الرد

| الرمز | العربية | نهائية؟ |
|-------|---------|---------|
| `IN_PROGRESS` | قيد التنفيذ | لا |
| `INTERNAL_REVIEW` | مراجعة داخلية | لا |
| `HOLD` | معلق | لا |
| `CANCELED` | ملغى | نعم |

#### مرحلة التقديم

| الرمز | العربية | نهائية؟ |
|-------|---------|---------|
| `NOT_APPROVED` | غير معتمد | لا |
| `SUBMITTED` | تم التقديم | لا |
| `LOST` | خاسر | نعم |

#### مرحلة التعاقد

| الرمز | العربية | نهائية؟ |
|-------|---------|---------|
| `WON` | فائز | لا |
| `CONTRACT_NEGOTIATION` | تفاوض العقد | لا |
| `CONTRACT_SIGNED` | عقد موقّع | نعم |

### 4.3 حالات «مملوكة للمحرك» (لا تُغيَّر من كانبان مباشرة)

هذه الحالات لها آثار جانبية، لذلك تُنفَّذ عبر **إجراء مخصص** وليس عبر تغيير الحالة العام:

| الحالة | الإجراء الصحيح |
|--------|----------------|
| `INTERNAL_REVIEW` | تعليم العرض جاهزاً للمراجعة |
| `HOLD` | تعليق الفرصة (مع سبب) |
| `CANCELED` | إلغاء الفرصة (مع سبب) |
| `NOT_QUALIFIED` | قرار بوابة (رفض / غير مؤهل / لم يجتز) |
| `NOT_APPROVED` | رفض اعتماد الإدارة |
| `SUBMITTED` | تقديم الفرصة |
| `WON` / `LOST` | تسجيل نتيجة العميل |
| `CONTRACT_SIGNED` | اعتماد توقيع العقد |

## 5) بوابات الاعتماد (Workflow Gates)

| الرمز | الاسم العربي | الدور المسؤول | القرارات | ماذا يحدث؟ |
|-------|--------------|---------------|----------|------------|
| `GW1_REVIEW` | مراجعة البوابة الأولى | BIDS_PRESALES | Approve / Reject | الرفض → غير مؤهل + بريد؛ القبول → اختيار مسار التأهيل |
| `QUAL_DECISION` | تأهيل خط الخدمة | SL أو PRESALES | Qualified / NotQualified | ينقل إلى مؤهل أو غير مؤهل |
| `QUAL_MEETING` | نتيجة اجتماع التأهيل | BIDS_MGMT | Passed / NotPassed | ينقل إلى مؤهل أو غير مؤهل |
| `PROPOSAL_REVIEW` | مراجعة العرض | PRESALES | Approve / Return | الإرجاع يعيد البناء ويفتح جولة جديدة؛ القبول يفتح اعتماد الإدارة |
| `MGMT_APPROVAL` | اعتماد الإدارة | MGMT | Approve / Reject | الرفض يعيد للبناء؛ القبول يجهّز للتقديم |
| `CONTRACT_SIGNOFF` | اعتماد العقد | MGMT | Approve / Reject | القبول → عقد موقّع |

> في قرارات الرفض/الإرجاع عادةً **يُطلب سبب** إلزامي.

## 6) المسار السعيد (Happy Path) — خطوة بخطوة

اتبع هذه الخطوات بالترتيب لتمرير فرصة من الإنشاء حتى توقيع العقد.

### الخطوة 1 — إنشاء الفرصة

1. سجّل الدخول كـ `am.sara@crm.local` أو `bids.presales@crm.local` أو `admin@crm.local`.
2. من **الفرص** → **إنشاء**.
3. أدخل: الاسم، العميل، القيمة المتوقعة، القناة، السمة، نوع الارتباط…
4. احفظ.

**النتيجة:** الحالة `بانتظار التقييم` + فتح بوابة `GW1_REVIEW` + إشعار/بريد استلام.

---

### الخطوة 2 — مراجعة البوابة الأولى (GW1)

1. سجّل الدخول كـ `bids.presales@crm.local`.
2. افتح الفرصة → تبويب **الاعتمادات** أو من **مركز الإجراءات** أو شاشة الاعتمادات.
3. قرّر **Approve**.

**النتيجة:** يظهر حوار **اختيار مسار التأهيل**.

---

### الخطوة 3 — اختيار مسار التأهيل

| الخيار | المعنى | الخطوة التالية |
|--------|--------|----------------|
| لا يحتاج اجتماع تأهيل | مسار خط الخدمة مباشرة | بوابة `QUAL_DECISION` |
| يحتاج اجتماع تأهيل | مسار الاجتماع | بوابة `QUAL_MEETING` + إدارة الاجتماع |

نفّذ الاختيار من الحوار أو من شاشة التأهيل.

---

### الخطوة 4أ — قرار خط الخدمة (بدون اجتماع)

1. سجّل الدخول كـ `sl.noura@crm.local` أو `presales.omar@crm.local`.
2. قرّر **Qualified**.

**النتيجة:** الحالة `مؤهل`.

---

### الخطوة 4ب — اجتماع التأهيل (مع اجتماع)

1. كـ Bids Management: أنشئ/حدّث الاجتماع والحضور والمحضر عند الحاجة.
2. قرّر **Passed**.

**النتيجة:** الحالة `مؤهل`.

---

### الخطوة 5 — تعيين المنفّذ (Assign Builder)

1. من مركز الإجراءات أو شاشة العرض: **تعيين المنفّذ**.
2. اختر نوع المنفّذ (Presales أو Service Line) والمستخدم والمواعيد إن لزم.

**النتيجة:** الانتقال إلى مرحلة **تطوير الرد** بحالة `قيد التنفيذ`، والمالك = المنفّذ، مع إشعار للمنفّذ.

> يمكن أيضاً سحب البطاقة في الكانبان إلى عمود «تطوير الرد»؛ إن كان الإجراء التالي تعيين منفّذ فسيُفتح نفس الحوار تلقائياً.

---

### الخطوة 6 — بناء العرض

يعمل المنفّذ (أو الفريق) على:

1. المواعيد النهائية (تقديم / داخلي…).
2. التكلفة التقديرية.
3. التسعير الحالي (Pricing) — **إلزامي قبل الجاهزية/التقديم**.
4. نطاق العمل وردود خطوط الخدمة عند الحاجة.
5. **خطاب الضمان (Bid Bond)** إن كانت الفرصة تتطلبه — مسار موازٍ يجب أن يصل إلى حالة **Issued** قبل التقديم.

---

### الخطوة 7 — تعليم العرض جاهزاً للمراجعة

1. من شاشة العرض: **Mark Ready / جاهز للمراجعة**.

**النتيجة:** الحالة `مراجعة داخلية` + فتح بوابة `PROPOSAL_REVIEW`.

---

### الخطوة 8 — مراجعة العرض

1. سجّل الدخول كـ `presales.omar@crm.local`.
2. قرّر **Approve**.

**النتيجة:** فتح بوابة `MGMT_APPROVAL` + طلب اعتماد.

---

### الخطوة 9 — اعتماد الإدارة

1. سجّل الدخول كـ `mgmt.fahad@crm.local`.
2. قرّر **Approve**.

**النتيجة:** الفرصة جاهزة للتقديم (مع بقاء أي فحوصات: تسعير، خطاب ضمان…).

---

### الخطوة 10 — التقديم

1. سجّل الدخول كـ `bids.mgmt@crm.local`.
2. من شاشة التقديم نفّذ **Submit**.

**شروط شائعة:** تسعير حالي موجود + اعتماد إدارة موافق + خطاب ضمان صادر إن كان مطلوباً.

**النتيجة:** الحالة `تم التقديم`.

---

### الخطوة 11 — تسجيل النتيجة

1. عند إعلان العميل: سجّل **Won** أو **Lost**.

| النتيجة | الحالة | ماذا بعدها؟ |
|---------|--------|-------------|
| Lost | خاسر (نهائية) | نهاية المسار |
| Won | فائز | يُنشأ عقد تلقائياً → مرحلة التعاقد |

---

### الخطوة 12 — التعاقد

1. أدر جولات التفاوض / بيانات العقد.
2. افتح بوابة `CONTRACT_SIGNOFF` ودع الإدارة تعتمد.
3. عند الاعتماد: الحالة `عقد موقّع` (نهائية).

## 7) البيزنس كيسز البديلة (Alternate Cases)

### BC-01 — رفض البوابة الأولى

- **من:** GW1 → Reject (مع سبب)
- **النتيجة:** `غير مؤهل` + بريد رفض
- **ملاحظات:** مسار مغلق نهائياً لهذه الفرصة

### BC-02 — غير مؤهل من خط الخدمة

- **من:** QUAL_DECISION → NotQualified (سبب)
- **النتيجة:** `غير مؤهل`

### BC-03 — رسوب اجتماع التأهيل

- **من:** QUAL_MEETING → NotPassed (سبب)
- **النتيجة:** `غير مؤهل`

### BC-04 — إرجاع العرض للمنفّذ

- **من:** PROPOSAL_REVIEW → Return (سبب)
- **النتيجة:** العودة إلى `قيد التنفيذ` + إعادة فتح بوابة المراجعة بجولة أعلى (Round++)
- **التكرار:** يمكن تكرار البناء ↔ الإرجاع عدة مرات

### BC-05 — رفض اعتماد الإدارة

- **من:** MGMT_APPROVAL → Reject (سبب)
- **النتيجة:** مرور عبر `غير معتمد` ثم العودة للبناء مع إعادة فتح مراجعة العرض
- **التكرار:** حلقة تصحيح أسعار/عرض ثم إعادة الاعتماد

### BC-06 — حظر التقديم بسبب خطاب الضمان

- **الشرط:** الفرصة تتطلب Bid Bond ولم تصل حالة الضمان إلى Issued
- **النتيجة:** رفض العملية (خطأ أعمال) حتى يُصدر الضمان

### BC-07 — حظر التقديم بسبب نقص التسعير

- **الشرط:** لا يوجد تسعير حالي (IsCurrent)
- **النتيجة:** لا يُسمح بالتقديم / يظهر Blocker في مركز الإجراءات

### BC-08 — تعليق الفرصة (Hold)

1. من تفاصيل الفرصة (أدوار Bids): **Hold** مع سبب.
2. تُحفظ الحالة والمرحلة السابقتان.
3. الحالة تصبح `معلق`.

### BC-09 — استئناف من التعليق (Resume)

1. **Resume** من مركز الإجراءات أو التفاصيل.
2. تُستعاد الحالة السابقة.

### BC-10 — إلغاء الفرصة (Cancel)

1. **Cancel** مع سبب (BIDS_PRESALES / BIDS_MGMT / ADMIN).
2. تتحول إلى `ملغى` المناسب لمرحلة التأهيل أو تطوير الرد.
3. الفرصة تُغلق.

### BC-11 — خسارة بعد التقديم

- تسجيل Outcome = Lost → حالة نهائية `خاسر`

### BC-12 — فوز ثم تعاقد

- Outcome = Won → عقد جديد → تفاوض → اعتماد توقيع → `عقد موقّع`

### BC-13 — محاولة انتقال غير قانوني

- مثال: سحب بطاقة كانبان إلى مرحلة لا يوجد لها انتقال مسموح من الحالة الحالية
- **النتيجة:** رسالة أن المرحلة ليست خطوة تالية قانونية، ويجب إكمال إجراء سير العمل الحالي

### BC-14 — محاولة النقل أثناء بوابة معلّقة

- **النتيجة:** النقل يُمنع؛ إن كان المستخدم مخوّلاً يُفتح حوار قرار البوابة

### BC-15 — نقل يتطلب سبب أو اختيار حالة

- عند وجود أكثر من حالة مستهدفة في المرحلة، أو انتقال يتطلب سبباً، يُفتح **حوار النقل** لإدخال البيانات قبل التنفيذ

## 8) واجهة الفرص — القائمة والكانبان والتقويم

### 8.1 عرض القائمة (List)

- جدول قابل للفرز/الترقيم
- فلاتر وبحث وواجهات محفوظة (Saved Views)
- تصدير Excel بمعالج اختيار الحقول
- اختصارات: فرصي، معلّق لديّ، مفتوحة، مغلقة، متأخرة، خطاب ضمان…

### 8.2 عرض الكانبان (Kanban) مع السحب والإفلات

1. بدّل العرض إلى **كانبان**.
2. الأعمدة = **المراحل الأربع**.
3. اسحب البطاقة من مقبض السحب إلى عمود مرحلة أخرى.

| السيناريو | سلوك النظام |
|-----------|-------------|
| نفس العمود | لا تغيير |
| بطاقة مغلقة | السحب معطّل |
| بوابة معلّقة | منع النقل + فتح قرار البوابة إن أمكن |
| الهدف = تطوير الرد والإجراء = تعيين منفّذ | فتح حوار تعيين المنفّذ |
| انتقال واحد بلا سبب | تنفيذ فوري |
| عدة حالات أو يلزم سبب | فتح حوار النقل |
| لا انتقال قانوني | رسالة خطأ |

### 8.3 عرض التقويم (Calendar)

- شبكة شهرية تعتمد على `موعد التقديم` و`الموعد الداخلي`
- التنقّل بين الأشهر والعودة لليوم الحالي
- النقر على الحدث يفتح الفرصة

### 8.4 تفاصيل الفرصة

| العنصر | الوظيفة |
|--------|---------|
| شريط الحالة | يُظهر موضع الفرصة في المراحل |

## 12) ملخص تدفق الحالات (مرجع بصري نصي)

```
[إنشاء]
   ↓
بانتظار التقييم ──GW1 Reject──► غير مؤهل ✕
   │
GW1 Approve → اختيار المسار
   ├─ بدون اجتماع → QUAL_DECISION
   │                    ├ Qualified
   │                    └ NotQualified ✕
   └─ باجتماع → QUAL_MEETING
                    ├ Passed
                    └ NotPassed ✕
   ↓
مؤهل → تعيين منفّذ
   ↓
قيد التنفيذ ↔ (إرجاع من مراجعة العرض)
   ↓ Mark Ready
مراجعة داخلية → PROPOSAL_REVIEW
   ├ Return → قيد التنفيذ (جولة++)
   └ Approve → MGMT_APPROVAL
                  ├ Reject → حلقة تصحيح
                  └ Approve → Submit
                                 ↓
                            تم التقديم
                         ├ Lost ✕
                         └ Won → تفاوض عقد → توقيع ✕ نهائي
```

يمكن في أي وقت تقريباً (قبل الإغلاق): **Hold** أو **Cancel** وفق الصلاحية والسبب.

## 13) قائمة تحقق سريعة للاختبار الشامل

استخدم هذه القائمة للتحقق أن كل البيزنس كيسز تعمل:

- [ ] إنشاء فرصة تظهر في القائمة والكانبان والتقويم (إن وُجدت مواعيد)
- [ ] GW1 قبول → مسار بدون اجتماع → Qualified → تعيين منفّذ → In Progress
- [ ] GW1 قبول → مسار باجتماع → Passed → تعيين منفّذ
- [ ] GW1 رفض → غير مؤهل
- [ ] QUAL / Meeting رفض → غير مؤهل
- [ ] بناء تسعير → Mark Ready → مراجعة Approve → اعتماد Approve → Submit
- [ ] إرجاع العرض ثم إعادة الجاهزية
- [ ] رفض الإدارة ثم التصحيح وإعادة الاعتماد
- [ ] Submit يفشل بدون تسعير / بدون ضمان مطلوب
- [ ] Outcome Lost
- [ ] Outcome Won → عقد → Sign-off → عقد موقّع
- [ ] Hold ثم Resume
- [ ] Cancel مع سبب
- [ ] سحب كانبان قانوني / غير قانوني / مع سبب / مع بوابة معلّقة
- [ ] صفحات السجل بين فرص القائمة
- [ ] النقاش (Chatter) والأنشطة والأزرار الذكية
- [ ] التقارير ولوحة المعلومات تظهر بيانات
- [ ] تبديل اللغة عربي ↔ إنجليزي مع RTL

## 14) ملاحظات تقنية مختصرة للفريق

- الـ SPA يوجّه `/api` إلى منفذ الـ API (غالباً 5088).
- للتطوير السريع بدون SQL: `Database__UseInMemory=true`.
- الانتقالات القانونية تُقرأ من جدول `StatusTransitions`؛ البوابات من `WorkflowGates`.
- واجهة `available-transitions` تُخفي الحالات المملوكة للمحرك وتُبيّن إن كان الانتقال يتطلب سبباً.
